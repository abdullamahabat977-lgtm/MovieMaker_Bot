# د Movie Studio v2 د جوړولو نقشه

## ثابتې پرېکړې

- اپلیکیشن د لاسي 3D فلم جوړولو لپاره دی؛ AI ویډیو نه تولیدوي.
- اصلي 3D شتمنۍ چې د اپ له خوا برابرېږي د APK دننه ساتل کېږي.
- د کاروونکي جوړ شوي کرکټرونه، پروژې، فلمونه او صادر شوي ویډیوګانې په موبایل کې ساتل کېږي.
- Cloudflare د حساب، Telegram لینک، Points، USDT، پیکونو او اجازو معلومات ساتي؛ د فلم فایلونه نه ساتي.
- GitHub Actions یوازې APK جوړوي.

## د انجن پړاوونه

د حقیقي GLB ماډلونو د ښودلو لپاره Filament د OpenGL ES 3.0 وړتیا غواړي. د اپلیکیشن پخوانی OpenGL ES 2.0 نمونه‌یي renderer لرې شوی. دا لا بشپړ فلم جوړولو انجن نه دی؛ څو-ماډلیز صحنه او MP4 رینډر لا پاتې دي.

## د پړاوونو حالت

### بشپړ شوي په کوډ کې
- Android Gradle/Manifest او GitHub Actions APK workflow.
- د `Film Studio/MovieProjects` app-specific فولډر، د ذخیرې د لیکلو/لوستلو چک، د پخوانیو پروژو انتقال او خوندي JSON لیکل.
- د هرې پروژې لومړنۍ صحنه، 720p او 24 FPS تنظیم.
- د صحنې ایډیټر د پروژې له لېست څخه پرانیستل.
- د حقیقي GLB ماډلونو محلي واردول، انتخاب، نوم بدلول، موقعیت/اندازه بدلول، د X/Y/Z پر محور څرخول، دقیق عددي transform، کاپي او حذف.
- د GLB اصلي texture او PBR موادو ساتل؛ د مصنوعي کارتوني پوستکي/کمیس رنګ‌بدلوونکي لرې کول.
- د Timeline د حرکت کلیپونو ثبت، ترتیب او حذف؛ د فریمونو موده، د فلم ساعت (HH:mm:ss) له مخې پیل/پای او د حرکت سرعت ثبتول.
- د صحنې د ځمکې اندازه او د فلم د پیل/پای ساعتونه ثبتول.
- د کمرې شاټونو موقعیت، د لید هدف، FOV او د شاټ وخت ثبتول.
- د حقیقي ماډلونو سرچینو پاڼو ته لاسرسی او د ډاونلوډ شوي GLB محلي واردول.
- د GL view د Activity lifecycle اداره.
- د Filament ګډ GLB scene renderer: تر ۸ ماډلونو او ۸۰ MB پورې؛ د اصلي mesh، PBR موادو، textures او د هر ماډل transform ساتل.
- د جلا GLB مخکتنې embedded skeletal animation ټاکل، درول او بیا چلول.

### پاتې پړاوونه
1. د ګډ scene renderer کې د ټچ له لارې د ماډل پېژندنه/انتخاب او د انتخاب شوي ماډل د transform live update.
2. د ځمکې حقیقي متريکي scale، grid/ground mesh او د توکو د ریښتینې اندازې مطابق صحنه.
3. د کمرې شاټونو واقعي Filament camera switching، preview او د فلم رینډر ته نښلول.
4. د حقیقي GLB ماډلونو قانوني، جواز-روښانه starter pack جوړول؛ اوسنی آنلاین کتابتون سرچینې پرانیزي، خو ماډلونه باید ډاونلوډ او بیا وارد شي.
5. د Timeline له لارې د embedded animation انتخاب، د حرکتونو blend، د keyframe editor او له GLB بهر د نوي skeletal rig جوړول.
6. رڼا، مواد او بشپړ scene settings.
7. د غږ او ډیالوګ ټریکونه، waveform او sync.
8. د څو صحنو Timeline او د صحنو ترمنځ انتقال.
9. د فریم رینډر، H.264/MP4 صادرول او د موبایل د ذخیرې مدیریت.
10. د ټیټ حافظې Android موبایل پر حقیقي وسیله د اوږدې مودې ازموینه.

## د APK جوړولو موقتي تګلاره

- د پراختیا په موده کې اتومات push-triggered build بند دی؛ workflow یوازې په لاس د workflow_dispatch له لارې چلېږي.
- تر هغه نوې APK نه جوړېږي چې د حقیقي assets، scene editing، animation/timeline، camera/light، audio، multi-scene او export اصلي برخې د ازموینې وړ نه وي.

## د کیفیت اصول

- د کمزوري موبایل لپاره Low-poly ماډلونه او 720p لومړنی هدف.
- په هر فریم کې بې ضرورته حافظه/آبجکټونه مه جوړوئ.
- د فایل خوندي کول باید د پخوانۍ پروژې خوندي کاپي وساتي.
- هره ځانګړنه باید جلا compile او device test ولري.
- تر عملي ازموینې مخکې د حل یا بریالیتوب ادعا مه کوئ.
