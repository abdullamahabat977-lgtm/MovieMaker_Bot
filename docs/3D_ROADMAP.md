# د Movie Studio v2 د جوړولو نقشه

## ثابتې پرېکړې

- اپلیکیشن د لاسي 3D فلم جوړولو لپاره دی؛ AI ویډیو نه تولیدوي.
- اصلي 3D شتمنۍ چې د اپ له خوا برابرېږي د APK دننه ساتل کېږي.
- د کاروونکي جوړ شوي کرکټرونه، پروژې، فلمونه او صادر شوي ویډیوګانې په موبایل کې ساتل کېږي.
- Cloudflare د حساب، Telegram لینک، Points، USDT، پیکونو او اجازو معلومات ساتي؛ د فلم فایلونه نه ساتي.
- GitHub Actions یوازې APK جوړوي.

## د انجن پړاوونه

د حقیقي GLB ماډلونو د ښودلو لپاره Filament د OpenGL ES 3.0 وړتیا غواړي. د اپلیکیشن پخوانی OpenGL ES 2.0 نمونه‌یي renderer لرې شوی. دا لا بشپړ فلم جوړولو انجن نه دی؛ څو-ماډلیز صحنه او MP4 رینډر لا پاتې دي.

## د پړاوونو حالت

### بشپړ شوي په کوډ کې
- Android Gradle/Manifest او GitHub Actions APK workflow.
- د پروژې محلي JSON فایل او خوندي لیکل.
- د هرې پروژې لومړنۍ صحنه، 720p او 24 FPS تنظیم.
- د صحنې ایډیټر د پروژې له لېست څخه پرانیستل.
- د حقیقي GLB ماډلونو محلي واردول، انتخاب، نوم بدلول، موقعیت/اندازه بدلول، کاپي او حذف.
- د GLB اصلي texture او PBR موادو ساتل؛ د مصنوعي کارتوني پوستکي/کمیس رنګ‌بدلوونکي لرې کول.
- د Timeline د حرکت کلیپونو ثبت، ترتیب او حذف.
- د GL view د Activity lifecycle اداره.

### پاتې پړاوونه
1. د څو GLB ماډلونو ګډ scene renderer او د هر توکي مستقل transform؛ اوس مهال هر GLB جلا مخکتل کېږي.
2. د څو ماډلونو هممهاله رینډر او د هر توکي مستقل transform.
3. د Timeline له لارې د embedded animation انتخاب، د حرکتونو blend او keyframe کنټرول؛ له GLB بهر د نوي skeletal rig جوړول.
4. د کمرې شاټونه، رڼا، مواد او scene settings.
5. د غږ او ډیالوګ ټریکونه، waveform او sync.
6. د څو صحنو Timeline او د صحنو ترمنځ انتقال.
7. د فریم رینډر، H.264/MP4 صادرول او د موبایل د ذخیرې مدیریت.
8. د ټیټ حافظې Android موبایل پر حقیقي وسیله د اوږدې مودې ازموینه.

## د کیفیت اصول

- د کمزوري موبایل لپاره Low-poly ماډلونه او 720p لومړنی هدف.
- په هر فریم کې بې ضرورته حافظه/آبجکټونه مه جوړوئ.
- د فایل خوندي کول باید د پخوانۍ پروژې خوندي کاپي وساتي.
- هره ځانګړنه باید جلا compile او device test ولري.
- تر عملي ازموینې مخکې د حل یا بریالیتوب ادعا مه کوئ.
