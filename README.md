# Movie Studio — د فلم سټوډیو

دا د Android لپاره د لاسي **3D فلم جوړولو** اپلیکیشن دی. کاروونکی خپل 3D کرکټرونه، چاپېریالونه، ماډلونه، حرکتونه، کامره، رڼا، ډیالوګ او غږونه پخپله تنظیموي. **AI فلم نه جوړوي.**

## مهم اصول

- فلمونه، پروژې، کرکټرونه او د کاروونکي وارد شوي فایلونه یوازې د موبایل په داخلي ذخیره کې ساتل کېږي.
- د کاروونکي فلمونه او ویډیوګانې Cloudflare ته نه پورته کېږي.
- د نوې پروژې جوړول، د پروژو لېست، د 3D مخکتنه او د محلي پیلني توکو کتل د حساب له نښلولو پرته هم کار کوي.
- Cloudflare D1 یوازې د حسابونو، Telegram لینک، Points، USDT، پېرودونو او د پیکونو د اجازو معلومات ساتي.
- GitHub Actions یوازې د Android APK د جوړولو او ازموینې لپاره دی؛ د اپلیکیشن ډیټابیس یا د کاروونکو د فایلونو ذخیره نه ده.
- د بوټ ټوکن او د سرور رازونه یوازې د Cloudflare Worker Secrets کې ساتل کېږي؛ په APK یا GitHub کوډ کې یې مه لیکئ.

## Android پېژندنه

- Package: `com.moviestudio.filmmaker`
- Min SDK: 23
- Compile / Target SDK: 35
- Java: 17
- Kotlin: 2.0.21
- Android Gradle Plugin: 8.7.3
- Gradle: 8.9

## د Git څانګې

- `main`: پخوانۍ نسخه؛ د بېرته ستنېدو لپاره ساتل شوې.
- `backup-before-rebuild-20261109`: د بیا جوړولو مخکې د `main` بشپړه خوندي کاپي.
- `rebuild-v2`: د نوې نسخې د جوړولو فعاله څانګه.

تر څو نوې نسخه جوړه او وازمویل شي، د پخوانۍ نسخې څانګه مه حذفوئ.

## د نوې نسخې اوسنی پړاو

1. د Android Gradle/Manifest بنسټ او د GitHub Actions APK جوړولو workflow فعال دي.
2. د Telegram حساب لپاره Worker API مراجع ساتل شوې؛ حسابي معلومات د فلم فایلونو څخه جلا دي.
3. د پروژو محلي JSON ذخیره د خوندي موقتي فایل او backup له لارې کار کوي.
4. د هرې نوې پروژې لپاره لومړنۍ صحنه، 720p تنظیم، 24 FPS، د توکو لېست او Timeline جوړېږي.
5. د صحنې ایډیټر د پروژې له لېست څخه پرانیستل کېږي.
6. کرکټر، مکعب او چاپېریال د صحنې توکو په توګه ورزیاتېدای، ټاکل کېدای، ځای بدلولای، اندازه بدلولای او حذف کېدای شي.
7. د پوستکي او کمیس د رنګونو انتخاب د توکي په معلوماتو کې خوندي کېږي.
8. د ولاړ حالت، قدم، منډې او خبرو Timeline کلیپونه د پیل فریم او مودې سره ثبتېږي؛ دا مهال کلیپونه د حرکت معلومات دي، بشپړ skeletal animation playback نه دی.
9. د واقعي کرکټرونو لپاره د GLB فایل واردول؛ فایلونه د پروژې په محلي `assets/characters/` فولډر کې ساتل کېږي.
10. د Filament پر بنسټ GLB مخکتنه د ماډل حقیقي mesh، PBR مواد او textures ښيي؛ د skeleton او animation Timeline کنټرول لا راتلونکی پړاو دی.
11. د OpenGL ES 2.0 مخکتنه لا هم یوازې د ساده مکعب/پخواني نمونوي شکلونو لپاره ده؛ د واقعي انسان ښودلو لپاره وارد شوی GLB وکاروئ.
12. د صحنې توکي، بدلونونه او Timeline یوازې د موبایل په داخلي ذخیره کې پاتې کېږي.

## لا نه بشپړې شوې برخې

د وارد شوي GLB ماډل د صحنې په اصلي څو-توکیز renderer کې ګډول، د GLB له skeleton بهر د نوي skeletal rig جوړول او د کی‌فریمونو د Timeline کنټرول، څو-توکیز بشپړ scene rendering، د کمرې/رڼا ایډیټر، د غږ/ډیالوګ ټریکونه، د صحنو بشپړ Timeline، او MP4 صادرول لا راتلونکي کارونه دي. د CI بریالی build د موبایل پر حقیقي وسیله ازموینې بدیل نه دی.

## د APK جوړول

په GitHub کې د `rebuild-v2` څانګې ته Push کول یا د Actions له لارې `Build Movie Studio APK` په لاس چلول د Debug APK جوړوي. فایل د Workflow د Artifacts برخه کې د `Movie-Studio-debug-apk` په نوم ښکته کېدای شي.

## د پروژې محلي جوړښت

د هر فلم معلومات او شتمنۍ په موبایل کې ساتل کېږي:

```text
MovieProjects/
  project_<id>/
    project.json
    assets/
      characters/
      environments/
      props/
      images/
      audio/
    exports/
```

د اپلیکیشن دننه ذخیره د نورو اپونو له عادي لاسرسي څخه جلا ده. د کاروونکي د غوښتنې له مخې فلمونه او صادر شوي فایلونه کلاوډ ته نه ځي.
