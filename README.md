# Movie Studio — د فلم سټوډیو

دا د Android لپاره د لاسي **3D فلم جوړولو** اپلیکیشن دی. کاروونکی خپل 3D کرکټرونه، چاپېریالونه، ماډلونه، حرکتونه، کامره، رڼا، ډیالوګ او غږونه پخپله تنظیموي. **AI فلم نه جوړوي.**

## مهم اصول

- فلمونه، پروژې، کرکټرونه او د کاروونکي وارد شوي فایلونه یوازې د موبایل په داخلي ذخیره کې ساتل کېږي.
- د کاروونکي فلمونه او ویډیوګانې Cloudflare ته نه پورته کېږي.
- د نوې پروژې جوړول، د پروژو لېست، د 3D مخکتنه او د محلي پیلني توکو کتل د حساب له نښلولو پرته هم کار کوي.
- Cloudflare D1 یوازې د حسابونو، Telegram لینک، Points، USDT، پېرودونو او د پیکونو د اجازو معلومات ساتي.
- GitHub Actions یوازې د Android APK د جوړولو او ازموینې لپاره دی؛ د اپلیکیشن ډیټابیس یا د کاروونکو د فایلونو ذخیره نه ده.
- د بوټ ټوکن او د سرور رازونه یوازې د Cloudflare Worker Secrets کې ساتل کېږي؛ په APK یا GitHub کوډ کې یې مه لیکئ.

## Android پېژندنه

- Package: `com.moviestudio.filmmaker`
- Min SDK: 23
- Compile / Target SDK: 35
- Java: 17
- Kotlin: 2.0.21
- Android Gradle Plugin: 8.7.3
- Gradle: 8.9

## د Git څانګې

- `main`: پخوانۍ نسخه؛ د بېرته ستنېدو لپاره ساتل شوې.
- `backup-before-rebuild-20261109`: د بیا جوړولو مخکې د `main` بشپړه خوندي کاپي.
- `rebuild-v2`: د نوې نسخې د جوړولو فعاله څانګه.

تر څو نوې نسخه جوړه او وازمویل شي، د پخوانۍ نسخې څانګه مه حذفوئ.

## د نوې نسخې اوسنی پړاو

1. د Android Gradle/Manifest بنسټ او د GitHub Actions APK جوړولو workflow فعال دي.
2. د Telegram حساب لپاره Worker API مراجع ساتل شوې؛ حسابي معلومات د فلم فایلونو څخه جلا دي.
3. د پروژو JSON، GLB ماډلونه او صادرات د `Film Studio/MovieProjects` په app-specific فولډر کې ساتل کېږي؛ د Android ځانګړې ذخیره د عمومي READ/WRITE اجازې ته اړتیا نه لري.
4. د پخوانۍ نسخې پروژې له `filesDir/MovieProjects` څخه نوي فولډر ته د نه‌اووررایټ کېدونکي انتقال هڅه کېږي.
5. د هرې نوې پروژې لپاره لومړنۍ صحنه، 720p تنظیم، 24 FPS، د توکو لېست او Timeline جوړېږي.
6. د صحنې ایډیټر د پروژې له لېست څخه پرانیستل کېږي.
7. د انسان، حیوان، موټر، ودانۍ، ونې، فرنیچر، جامو، وسایلو او نورو حقیقي GLB ماډلونو واردول او د صحنې توکو په توګه ثبتول فعال دي.
8. د وارد شوي ماډل نوم، موقعیت، اندازه، د X/Y/Z څرخول، کاپي او حذف په محلي پروژه کې خوندي کېږي؛ اصلي texture او مواد د GLB له فایل څخه راځي. د دقیقو شمیرو له لارې هم موقعیت، اندازه او درې واړه زاویې ټاکل کېدای شي.
9. د ځمکې پلنوالی/اوږدوالی او د فلم د پیل/پای ساعتونه ثبتېږي؛ د هر توکي حرکت د HH:mm:ss پیل/پای او سرعت سره هم مهالوېش کېدای شي. دا مهالوېش لا د skeletal animation playback سره نه دی تړل شوی.
10. د کمرې شاټونو نوم، موقعیت، د لید هدف، FOV او د شاټ وخت په صحنه کې ثبتېږي؛ د رینډر او ژوندۍ کمرې بدلولو سره نښلول لا پاتې دي.
11. د انسان، حیوان، موټر، ودانۍ، ونې، فرنیچر او نورو توکو GLB فایلونه د اړوند محلي assets فولډر کې ساتل کېږي.
12. د Filament پر بنسټ GLB مخکتنه د ماډل حقیقي mesh، PBR مواد او textures ښيي؛ که ماډل embedded animation ولري، په مخکتنه کې یې حرکت ټاکل او پلی کول شوني دي.
13. د صحنې ایډیټر کارتوني او هندسي انسان نه ښيي؛ د حقیقي انسان او نورو شیانو لپاره وارد شوی GLB 2.0 ماډل وکاروئ.
14. د صحنې توکي، بدلونونه او Timeline یوازې د موبایل په داخلي ذخیره کې پاتې کېږي.

## د حقیقي ماډلونو یادونه

د توکو کټګورۍ د نوملړ په بڼه دي او د حقیقي ماډلونو لپاره د آنلاین سرچینو لینکونه هم شته؛ ماډلونه په APK کې نه دي بنډل شوي. کارن د سرچینې له پاڼې GLB فایل ډاونلوډوي او بیا یې د اپک له لارې واردوي. د سرچینې د جواز او لیکوال کریډیټ شرطونه باید مراعت شي. وارد شوي ماډلونه جلا هم مخکتل کېږي او د پروژې د ټولې صحنې په ګډ 3D لید کې تر ۸ ماډلونو پورې یوځای ښودل کېدای شي؛ د موبایل د حافظې د ساتنې لپاره د صحنې د ماډلونو ټول حجم تر ۸۰ MB محدود دی. د هر فایل حد ۴۰ MB او د پروژې ټول محلي GLB فایلونه ۲۵۶ MB دي؛ په یوه صحنه کې تر ۳۲ توکو پورې واردېدای شي.

## لا نه بشپړې شوې برخې

په ګډه صحنه کې د توکو د ټچ له لارې ټاکل او مستقل transform کنټرول، د ثبت شوي کمرې شاټونو ژوندی preview او د رینډر سره نښلول، د ځمکې حقیقي متريکي grid، د GLB له skeleton بهر نوی skeletal rig او د کی‌فریم Timeline، د رڼا ایډیټر، د غږ/ډیالوګ ټریکونه، د څو صحنو Timeline، او MP4 صادرول لا راتلونکي کارونه دي. د CI بریالی build د موبایل پر حقیقي وسیله ازموینې بدیل نه دی.

## د APK جوړول

د پراختیا پر مهال اتومات APK جوړول بند دي. Workflow یوازې د GitHub Actions له workflow_dispatch لارې په لاس چلېږي؛ وروستۍ Build به هغه وخت پیل شي چې اصلي برخې بشپړې او د ازموینې لپاره چمتو وي.

## د پروژې محلي جوړښت

د هر فلم معلومات او شتمنۍ په موبایل کې ساتل کېږي:

```text
MovieProjects/
  project_<id>/
    project.json
    assets/
      characters/
      environments/
      props/
      images/
      audio/
    exports/
```

د اپلیکیشن دننه ذخیره د نورو اپونو له عادي لاسرسي څخه جلا ده. د کاروونکي د غوښتنې له مخې فلمونه او صادر شوي فایلونه کلاوډ ته نه ځي.
